# v0.2 — Claude Code JSONL ingestion + session picker

**Status:** ✅ built & verified (2026-06-24, after v0.1 launch). All five deliverables landed; 62 tests pass; verified end-to-end against real `~/.claude/projects` sessions (picker → ingest → replay with an intact 12/12 hash chain).
**Goal:** let traceglass ingest real Claude Code session logs and replay them in the existing dashboard, plus a session-picker landing screen when no run is specified.

This turns "scrub a sample fixture" into "scrub *your own* agent run." It is also the second launch moment: *"Day 1 traceglass replayed any agent run; this week it ingests your Claude Code sessions directly."*

## Why reference, not depend

We port a minimal JSONL parse rather than taking a runtime dependency on the `inspecto` package, to avoid version coupling. `inspecto` is cited as the reference implementation in code comments. No changes to the v1 `Run`/`Step` model.

## Deliverables

### 1. Core adapter — `packages/core/src/ingest/claude-code.ts`
Maps Claude Code session JSONL → `Run`/`Step` (existing model):
- `user` (string content) → `user_input`
- `assistant` `thinking` → `llm_reasoning`
- `assistant` `text` → `llm_reasoning`; the **final** assistant text of the session → `final_output`
- `assistant` `tool_use` → `tool_call` (with `toolName` + `input`)
- `user` `tool_result` → attached as the matching tool_call step's `output`; the structured `toolUseResult` becomes that step's `dataPayload` (the data the agent saw)
- token usage from each message's `usage` → `Step.tokens`; `cost` derived from a configurable model-price table (`model-prices.ts`), USD default
- `spanId` = entry `uuid`; `parentSpanId` = `parentUuid` (preserves the tree / sidechains)
- per-step `durationMs` derived from the gap to the next entry's timestamp (attributed to the first step of each entry, so wall-clock totals stay honest)

### 2. Core discovery — `packages/core/src/ingest/claude-code-sessions.ts`
- `defaultSessionsDir()` → `~/.claude/projects`
- `discoverSessions(dir?)` → scans `**/*.jsonl`, returns `{ id, file, project, startedAt, endedAt, messageCount, firstPrompt }`, newest first
- `readSessionRecords(file)` → parse a session's JSONL into records

### 3. CLI additions — `packages/cli/src/bin.ts`
- `traceglass sessions` — list discovered Claude Code sessions with labels
- `traceglass open --session <id>` — ingest + replay a specific session
- `traceglass open` (no trace-file, no `--id`, no `--session`) → boot to the **session picker** UI

### 4. Server endpoints — `packages/cli/src/server.ts`
- `GET /api/sessions` — discovered sessions
- `POST /api/sessions/:id/ingest` — ingest a session into the store, return `{ runId }`

### 5. Web — `packages/web/src/components/SessionPicker.tsx`
- Landing state when no `?run` is in the URL: choose a Claude Code session (or an already-ingested run), then ingest + replay into the existing dashboard. Reuses every existing component.

## Acceptance
- Pointed at a real Claude Code sessions dir, `traceglass sessions` lists them with sensible labels.
- Selecting one ingests into a schema-valid `Run` and replays with the full dashboard.
- Loop detection and the hash-chain integrity badge work on real session data.
- Token/cost totals reflect the session's real usage.
